Foundations

Colors

Every color token from tokens.json, in the current theme.

Foundations

Icon

Line icons in the lucide style: 24px grid, 2px stroke, round caps, drawn with currentColor. Shown at 16px in UI, 14px (sm) in chips and dense rows, 20px (lg) in empty states and error cards.

Actions

Button

Buttons start an action. Primary (accent-solid) appears at most once per view, for the thing the screen is for: "New project", "Start run", "Approve & merge to dev". Everything else is secondary.

Actions

IconButton

Icon-only button for the top bar, dialog close and row actions. label is required: it becomes the accessible name and the tooltip.

Status

Badge

Small labels for identity, not state. claude and codex are the provider badges on agents and runs; draft / published show an agent or skill's lifecycle ("Published v3"); neutral is for transport ("stdio", "http") and "self-hosted".

Status

Chip

Neutral metadata tag: a branch (dev · clean), a model name, "4 files", "Used by 2 agents", "attempt 2". Use mono for anything that's code: branch names, models, SHAs. Chips are read-only; interactive filters use the filter-chip pattern in the README.

Status

Kbd

Keyboard shortcut hint. Shown in the ⌘K search trigger, the command palette footer and next to menu items that have a shortcut. Use the platform glyphs: ⌘ ⇧ ↵ ↑ ↓ esc.

Status

StatusDot

An 8px health dot for infrastructure: Preview services, MCP servers, the sidebar host status, the global run indicator. Always next to a text label (pass it as children).

Status

StatusPill

The run state, everywhere a run appears: tables, cards, headers, popovers. It's the one place colour carries meaning, so the six states map to fixed tokens and are never reused for anything else.

Forms

SegmentedControl

Two to four mutually exclusive options that switch a view or a single setting: grid/table, unified/split diff, desktop/tablet/mobile preview, provider, filesystem scope, transport. Icon-only options need ariaLabel.

Forms

Switch

On/off setting that applies immediately (no Save button). For choices between more than two options use SegmentedControl; for settings saved with a form, a checkbox.

Forms

TextField

Labelled input. A visible label is mandatory (no placeholder-as-label); the label and help/error text are wired with htmlFor and aria-describedby.

Navigation

NavItem

Sidebar navigation row: Projects, Agents, Skills, Workflows, Executions, MCP Servers, Settings, in that order. The active item gets accent-soft fill and an accent icon. badge shows an amber count of runs awaiting approval on Executions. collapsed renders the 64px icon rail (label becomes the tooltip and aria-label).

Navigation

Tabs

Page-level sections of one entity: a project (Overview, Branches & Worktrees, Reviews, Preview, Settings) or a run (Logs, Diff, Tests). The selected tab gets the accent-solid underline.

Layout

Card

The default container: surface fill, border hairline, radius-lg. A header row holds the title (card-title style) and at most two small actions. flush lets lists and tables run edge to edge. Cards don't nest, and they don't take shadows: elevation is for things that float.

Feedback

Banner

Inline, persistent message inside a page, card, dialog or drawer. It stays until the condition changes.

Feedback

EmptyState

What a list shows when it has nothing, or when it failed to load. Every list in the app has both.

Feedback

Skeleton

Loading placeholder shaped like the content it replaces: card outlines, table rows, avatar squares. Show it only after ~150ms so fast loads don't flash; it respects reduced motion.

Feedback

Toast

Transient confirmation, bottom-right, stacking up to four, auto-dismissed after about 4.5s. Title states what happened in past tense ("Merged to dev · Preview rebuilding", "Project created"); the description adds the object (branch, name, commit). Errors that need action go in a Banner instead; a toast only reports them.

Overlays

Dialog

Modal for one decision or one short form: New project, Run task, Approve & merge, Request changes, Publish, and every destructive confirm.

Runs

DiffView

Unified diff of one file. Header: path in mono, green +additions and red −deletions. Rows: old and new line numbers, a sign column, the text; additions on run-succeeded-soft, deletions on run-failed-soft, hunk headers on run-running-soft. Pair it with a file tree on the left (selected file on accent-soft). A split view puts old and new side by side with hatched filler where one side is empty.

Runs

LogViewer

Live CLI output. Monospace (code style, 20px rows), line numbers, collapsible sections per lifecycle step, and these tones: system (studio messages, accent), command ($ lines, bold), edit (file writes, blue), ok, error, warn, tool, dim.

Runs

RunTimeline

The fixed run lifecycle: Queued → Preparing worktree → Running CLI → Tests → Awaiting approval → Merged. Done steps get a green check, the current step pulses blue, an approval gate pulses amber, and a failure turns red with an ✕. Don't add custom steps for agent-internal phases; those live in the log sections.
